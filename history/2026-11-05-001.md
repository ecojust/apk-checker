## 行动记录

### A1 · 首版桌面应用

- 从空仓库实现 Electron + React + TypeScript / Vite 界面和桌面进程；APK 存储与解析在 `electron/library.ts`，Android SDK / adb / Emulator / scrcpy 控制在 `electron/android.ts`。
- 实现软件库导入与去重、实际安装后桌面记录、按手机／电视 AVD 打开、卸载、运行环境设置、等待与失败反馈。每种模式共享一台设备及其前台显示窗口，不是一款应用一台独立 Android 实例。
- 加入跨平台构建、52 项单元测试及中文配置说明。实际 Electron 验证过渲染、preload IPC、设置持久化、参数校验；浏览器 fixture 流程不作为真实 APK 成功证据。
- 提交：[fec8430](https://github.com/ecojust/apk-checker/commit/fec8430)，`feat: add Android desktop with APK library and phone/TV modes`。
- 验证：`npm run check`、`npm test`、`npm run build` 通过；[三平台 CI](https://github.com/ecojust/apk-checker/actions/runs/42036490652) 生成 macOS arm64、macOS x64 和 Windows x64 安装包。
- 限制：该轮未配置 Developer ID 签名、公证或 Windows 代码签名。构建成功未证明用户下载后的 Gatekeeper 行为；用户后续反馈 ARM 版「已损坏」，见 A5。

- 实际 aapt 解析：名称「麦动」、包名 `com.local.ktv`、版本 `2.1.8` / versionCode `11`、minSdk 21、targetSdk 25。仅包含 `arm64-v8a` 和 `armeabi-v7a` 原生库，未包含 x86 / x86_64 库。

### A3 · 实际 Android 模拟器测试

- 添加 `scripts/apk-smoke.ts` 和 `.github/workflows/apk-smoke.yml`，固定原版 APK 哈希，实际调用 `AppLibrary` 和 `AndroidRuntime`；保存截图、logcat、元数据与 JSON 结果，失败退出非零，不上传 APK 本体。
- 测试要求干净 AVD；安装前拒绝覆盖已有同包应用。安装后仅授予声明的读写存储权限，未授予麦克风权限。方向键检查是输入注入后的前台与进程存活检查，未断言每个控件的焦点移动。
- [第一轮标准镜像](https://github.com/ecojust/apk-checker/actions/runs/42038417727) 和[增加保护后的标准镜像](https://github.com/ecojust/apk-checker/actions/runs/42039273057) 中，Android 11 / API 30 / Google APIs / x86_64 手机组均通过导入、安装、持久化、scrcpy 视频窗口启动、前台进程检查、按键输入后的存活检查和卸载。
- 两轮 Android TV 12 / API 31 / x86 组在实际安装阶段失败，错误为 `INSTALL_FAILED_NO_MATCHING_ABIS`，未进入启动或播放阶段。该失败是已测试镜像与 ARM APK 的 ABI 不匹配，不能扩大为所有电视镜像或所有 Windows 设备都不支持。
- 初次 CI 工作流使用了 job 级 `runner.temp` 表达式，解析失败；已在 `74ca5aa` 修复为运行步骤中的路径设置。后续在 `5893e75` 加入已有应用保护、迟到运行时错误检查、错误 annotation 与可读摘要。
- 相关提交：`3da1dc2`、`74ca5aa`、`5893e75`。提交 message 均为英文。
- 当前补测：[Android TV API 36 / x86_64 工作流](https://github.com/ecojust/apk-checker/actions/runs/42040304820)，使用原版 APK 和官方 scrcpy 5.0.1。创建本条交接时尚未取得最终结果，不记为通过。配置提交为 `39b222a`、`714644b`。
- 限制：测试主机为 Linux CI；未完成 macOS / Windows 上真实 APK 运行验收，也未测试歌曲播放、FFmpeg 解码负载、录音、音频延迟、扫码点歌或 USB 设备。

### A4 · 框架性能答复

- 向用户解释 Electron 用于先接通跨平台界面和完整运行流程；建议长期可评估 Tauri 2 + Rust 以减小管理界面开销。
- 区分管理界面、Android 硬件虚拟化与 ARM 转译、scrcpy 编解码、APK 自身负载。未提供未经测量的帧率、内存或延迟数字；未把框架替换当作 ABI 兼容性修复。
- 当前实现仍为 Electron，未迁移框架。对原生模拟器窗口或 Tauri 的讨论属于建议，尚无对应实现或性能验收。

### A5 · macOS ARM「已损坏」与规范文件

- 用户报告 ARM 客户端打开后提示「已损坏」。目前确认原构建未配置正式签名／公证；具体签名或打包原因仍在核查，不能仅凭提示断言根因。
- macOS 打包任务由并行 agent 排查 `package.json`、构建工作流、签名与 DMG 内应用完整性，主 agent 待汇总验证结果和重新生成的产物。不以全局关闭 Gatekeeper 作为修复方案。
- 参考 [pureTV 的 AGENTS.md](https://github.com/ecojust/pureTV/blob/master/AGENTS.md) 和 `history/README.md`，新增本仓库 `AGENTS.md`、历史索引、记录规则和本记录；采用当前仓库结构，不复制 pureTV 的小游戏计数、Android APK 发布证书或 Tauri 已实现等无关约定。
- 用户要求的英文 Git commit message 已明确写入协作规范；中文用户沟通和文档不受此限制。
- 本次规范文件仅进行了内容、路径和 Git diff 检查，未因纯文档新增重跑全部测试。主 agent 仍需将最终 macOS 修复和新版 TV 测试结果追加到本记录及索引。

### A6 · macOS 0.1.1 修复代码与新版电视诊断

- 核查 electron-builder 26.18.0 的签名路径：原配置 `CSC_IDENTITY_AUTO_DISCOVERY=false` 且没有显式身份时会跳过重签名；PR 构建还可能额外跳过签名。修改后的 Electron 包可能保留失效的原签名，构建成功无法排除用户反馈的「已损坏」。
- 0.1.1 明确配置 ad-hoc 身份 `-`、Electron JIT / 辅助程序权限、严格签名检查，并对 PR 构建启用签名。未配置 Developer ID 或 Apple 公证，不能承诺下载隔离条件下无提示启动。
- 增加 `scripts/verify-macos-package.mjs`：在对应原生 macOS 主机核验 DMG、只读挂载后及复制后的代码签名、架构、实际应用启动、React / preload IPC 和 Node 隔离，记录 Gatekeeper 评估；另生成 `SHA256SUMS.txt`。
- 本地配置 schema、Node 脚本语法、plist 解析和校验和 helper 已检查；原生 DMG / 签名 / 启动证据仍待修复版 CI，不能提前计为通过。README 增加校验、安装及仅对可信应用解除下载隔离的说明。
- 新版电视首轮 [42040304820](https://github.com/ecojust/apk-checker/actions/runs/42040304820) 已成功安装 APK，失败发生在 scrcpy 打开 CI 声卡：`Could not open audio device`。这与 TV API 31 的 ABI 安装失败不同。
- 为没有实体声卡的 CI 设置 SDL dummy 音频输出，保留实际视频路径，不把它作为音频播放测试。复测 [42041208224](https://github.com/ecojust/apk-checker/actions/runs/42041208224) 正在运行；源码提交 `fbf9c28`。新结果需继续追加，不覆盖第一轮失败。
