# 用户请求与行动记录

本目录帮助后续 agent 从真实工作状态继续。先读 [INDEX.md](INDEX.md)，再读最新记录和相关未完成记录，同时核对实际 Git 状态及仓库文件。

## 记录方式

- 文件名为 `YYYY-MM-DD-NNN.md`，日期采用 UTC，序号从 `001` 递增。同一持续任务可跨日期追加；新的独立任务新建文件并登记索引。
- 用户 prompt 原样记录并编号，保留后续补充顺序；历史原文不可得时明确写“原文不可得”，不得编造。
- 每个有意义的阶段后追加实际动作、验证、证据和结果。判断有误时追加更正，保留原始记录；最终回复前写清交接状态。
- 状态使用 `in_progress`、`blocked`、`completed`、`cancelled`。`blocked` 说明具体缺项；只有该记录的用户目标全部完成才标记 `completed`。
- 仓库文件使用相对链接，提交和工作流使用完整链接；本次 scratch 路径标注“临时，后续环境可能不存在”，不得作为唯一交接入口。
- 记录证据摘要，不复制巨大日志。计划执行、执行中、失败、通过、未验证分别说明；测试数量来自实际输出。
- 区分 mock、实际 Electron、Android 模拟器、实体设备和宿主机测试；构建成功、签名有效、公证通过及安装可用也分别记录。
- 对外交接时注明history所在分支。将开发记录同步到默认分支时只同步需要的文档；尚未合并的证据使用固定提交链接，不能让相对链接指向默认分支中不存在的文件，也不能把日志同步描述为功能合并。
- 不保存秘密、完整敏感输出或私有推理。prompt 中秘密替换为 `[已脱敏：类型]` 并注明；其余文字保留原文。
- 多 agent 协作由主 agent 汇总日志；并行 agent 汇报结果，避免同时修改同一段记录。
- Git commit message 使用英文；本目录可使用中文。

## 模板

```markdown
# YYYY-MM-DD · 任务名称

- 状态：in_progress
- 分支：实际分支
- 起点：实际提交 SHA
- 关联记录：无／相对链接
- 当前目标与边界：用户要求及本次实际范围

## 用户 prompt

### U1

> 用户可见原文；无法取得的历史原文明示不可得

## 行动记录

### A1 · 阶段名称

- 动作与文件：实际做了什么。
- 决策摘要：采用方案的可复查依据。
- 验证与结果：实际执行命令、退出结果、必要计数。
- 证据：仓库文件、提交／工作流，或注明临时路径。
- 限制与未完成：尚未验证、未提交或未发布的部分。

## 当前交接

- 已完成：已核实结果。
- 正在进行／阻塞：准确状态及缺项。
- 下一步：可直接执行的步骤。
- 发布状态：提交、PR、安装包、签名、公证和 Release 分别说明。
```

`INDEX.md` 每条记录至少包含链接、状态、用户目标、当前结果和下一步，便于后续 agent 不必遍历所有旧记录。
