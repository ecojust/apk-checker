## 行动记录

### A1 · 核对实际启动路径及日志

- 克隆仓库到 `/workspace/apk-checker`（本次临时工作区），起点工作树干净，创建修复分支。读取 AGENTS、history 和实际代码；完成 `ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci`，未下载完整 Android 引擎／镜像。
- 已确认 `electron/android.ts` 使用 180 秒启动期限，与 APK 安装的 180 秒命令期限分别独立。后台安装转原生窗口会关闭并重新启动同一 AVD；原启动参数未跳过快照，且丢弃 stdout。
- 用户日志中的 QEMU `error while loading state ... goldfish_pipe` 明确指向恢复设备保存状态失败；退出代码 0 不能视为启动成功。日志本身不能证明快照失效的具体原因，不能据此改 GPU、镜像或归因为 macOS 键盘信息。
- 官方 [Emulator 参数说明](https://developer.android.com/studio/run/emulator-commandline)说明 `-no-snapshot-load` 冷启动并在退出时保存状态；[快照文档](https://developer.android.com/studio/run/emulator-snapshots)建议恢复失败时 Cold Boot。Android 用户数据与 Quick Boot 快照分离。
- 并行分工：实现 agent 仅修改 Android 启动代码及回归测试；独立审查 agent 核实资源、配置、官方资料和生命周期；主 agent 负责文档、历史、总体验证与交付。

### A2 · 向用户提供保留数据的临时冷启动方法

- 已告知用户完全退出 APK Checker 及模拟器，备份私有 TV AVD 的 `config.ini`，将 `fastboot.forceColdBoot=no` 改为 `fastboot.forceColdBoot=yes` 后重开软件。
- 目录依据既有用户现场记录及当前 AVD 命名：`~/Library/Application Support/apk-checker/managed-runtime/avds/APKChecker_TV_36_arm64_v8a.avd/`。未在用户当前 Mac 上执行或确认该目录；不应在找不到目录时新建空配置，也不删除快照／userdata。
- 自动恢复实现进行中：识别快照恢复错误、确认自有进程退出、仅一次冷启动重试；后台转原生窗口直接冷启动。保留真实安装成功边界、取消／退出边界和外部设备隔离。
